# QWEN.md – Garden Scripts Overview

## Project Context
This directory contains the core Unity C# scripts for the **Garden** mini‑game of the *the_spring* project. The scripts implement flower care mechanics, UI handling, drag‑and‑drop interactions, growth condition data, and supporting interfaces.

## Directory Structure
```
Assets/scripts/garden/
├─ DragDrop.cs                # Handles drag‑and‑drop for pots and cards
├─ Flower.cs                  # MonoBehaviour representing a flower instance
├─ FlowerCareSystem.cs        # Singleton managing flower list and drop‑zone feedback
├─ GardenUI.cs                # UI controller for shop, flower view and pot view panels
├─ GrowthConditions.cs        # ScriptableObject defining care timings & growth logic
├─ iCardDropArea.cs           # Interface for UI drop‑area components
├─ IGrowthStage.cs            # Interface for growth‑stage behaviours
├─ Pot*.cs (e.g., Pot.cs)     # Scripts for pot objects (not listed here but present)
├─ ... other helper scripts   # Various animation, interaction, and utility scripts
```
> **Note:** Unity `.meta` files are version‑controlled alongside the source scripts and should not be edited manually.

## Key Scripts
### `FlowerCareSystem.cs`
* Implements a **singleton** (`Instance`) for global access.
* Stores a `List<Flower>` of all registered flowers.
* Manages visual feedback for valid/invalid pot placement using a `SpriteRenderer` attached to a child object named `DropZoneHighlight`.
* Provides `RegisterFlower`, `UnregisterFlower`, `ShowDropZoneFeedback`, and `HideDropZoneFeedback` methods.
* Colors: semi‑transparent green for valid placement, red for invalid.

### `GardenUI.cs`
* Controls visibility of three main UI panels: **shop**, **flower view**, and **pot view**.
* Simple toggle methods (`ShowHideShop`, `flowerViewShow`, `potViewShow`) update internal bool flags and set panel `SetActive` accordingly.
* Holds a reference to a `gameplayButtons` panel for future extensions.

### `GrowthConditions.cs`
* A **ScriptableObject** used to define per‑species growth parameters.
* Exposes:
  * `stageSprites` – array of sprites for each growth stage.
  * Care timing fields (`TimeBetweenWatering`, `TimeBetweenFertilizing`, `TimeBetweenSunlight`).
  * Growth timing fields (`TimeToSprout`, `TimeToYoungShoot`, `TimeToBloom`).
  * Event‑count logic (`BaseEventCount`, `StageMultiplier`) with helper `GetRequiredEventsForStage(int)`.
* Includes `OnValidate` to clamp values to sensible ranges.

### `DragDrop.cs` (brief overview)
* Implements Unity `IDragHandler`, `IBeginDragHandler`, `IEndDragHandler` to allow pots (or cards) to be dragged onto valid zones.
* Calls `FlowerCareSystem.Instance.ShowDropZoneFeedback` during drag and `HideDropZoneFeedback` on end.

### Interfaces
* `iCardDropArea.cs` – defines contract for UI drop areas.
* `IGrowthStage.cs` – defines methods for progressing a flower through its growth stages.

## Development Conventions
* **Naming:** Classes use PascalCase; public fields serialized for the Unity inspector follow `camelCase` with `[SerializeField]` when private.
* **Singleton pattern:** Used in `FlowerCareSystem` for global access; `DontDestroyOnLoad` preserves it across scene changes.
* **ScriptableObject assets:** `GrowthConditions` assets should be created via `Assets → Create → Garden → Growth Conditions` and assigned to flower prefabs.
* **UI panel toggling:** Simple boolean flags stored locally; panel references are set via the Unity inspector.
* **Meta files:** `.meta` files are automatically generated by Unity; keep them in version control.

## Building & Running
1. Open the project folder in **Unity Hub** (`/mnt/c/Users/Chesterh/Desktop/the_spring`).
2. Ensure the Unity version matches the project's settings (check `ProjectSettings/ProjectVersion.txt`).
3. Press **Play** in the Unity Editor to test the garden mechanics.
4. For command‑line builds you can use Unity's batchmode, e.g.:
   ```bash
   Unity -batchmode -projectPath "/mnt/c/Users/Chesterh/Desktop/the_spring" -buildTarget StandaloneWindows64 -executeMethod BuildScript.PerformBuild -quit
   ```
   *(Replace `BuildScript.PerformBuild` with your project's build entry point.)*

## Testing
No automated Unity Test Framework tests are currently present in this folder. Manual testing steps:
1. Enter Play mode.
2. Verify that dragging a pot shows a green/red highlight depending on proximity to a valid drop zone.
3. Switch UI panels using the provided buttons and confirm panels appear/disappear.
4. Adjust values in a `GrowthConditions` asset and observe changes in flower growth timing.
